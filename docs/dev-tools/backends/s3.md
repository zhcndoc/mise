# s3 后端

`s3` 后端可从 Amazon S3 或 MinIO 等兼容存储下载二进制文件或归档文件。当访问权限应沿用 AWS 凭据，或版本来自存储桶列表时适合使用此后端；对于公开 URL 或受令牌保护的 URL，使用 [http 后端](/dev-tools/backends/http.html)更简单。此后端不需要 AWS CLI。

## 用法

将下方存储桶和对象键替换为当前平台可读取的制品，然后在当前项目中安装：

```sh
mise use 's3:my-tool[url=s3://my-bucket/tools/my-tool-v1.0.0.tar.gz]@1.0.0'
mise exec -- my-tool --version
```

请为参数加引号，以免 Shell 展开方括号。此命令会将以下内容写入 `mise.toml`。添加 `-g` 可全局安装工具。

```toml
[tools]
"s3:my-tool" = { version = "1.0.0", url = "s3://my-bucket/tools/my-tool-v1.0.0.tar.gz" }
```

URL 固定时，版本号仅用作标签。若要跟随版本发布，请在 URL 中加入版本号，并设置[版本发现](#version-discovery)。

## 身份验证

mise 使用 AWS SDK 的[默认凭据提供程序链](https://docs.aws.amazon.com/sdk-for-rust/latest/dg/credproviders.html)。它支持环境凭据、共享 AWS 配置文件、Web 身份，以及容器或实例角色。建议使用已有配置文件或工作负载角色，不要将长期访问密钥复制到项目配置中。

对于已配置的本地配置文件：

```sh
AWS_PROFILE=development AWS_REGION=us-east-1 mise install
```

临时环境凭据除了 `AWS_ACCESS_KEY_ID` 和 `AWS_SECRET_ACCESS_KEY`，还需要 `AWS_SESSION_TOKEN`。[`region`](#region) 工具选项可显式指定存储桶所在区域。

下载已知对象需要 `s3:GetObject` 权限。通过对象列表发现版本还需要 `s3:ListBucket` 权限；通过清单发现版本则需要清单的读取权限。下载成功并不能说明有权列出对象。

## 工具选项

### `url` {#url-required}

要下载的对象，格式为 `s3://<bucket>/<key>`。可在顶层设置，也可按平台设置 `platforms.<os>-<arch>.url`；工具必须设置其中一项。对象键支持模板：

```toml
[tools]
"s3:my-tool" = { version = "1.0.0", url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz" }
```

### `endpoint`

自定义的 S3 兼容端点，例如 MinIO、DigitalOcean Spaces 或自托管服务。设置端点后，mise 会使用路径风格的存储桶寻址方式。

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
endpoint = "https://minio.example.com"
```

### `region`

存储桶所在的 AWS 区域。未设置时，mise 会使用 AWS 配置中的区域，例如 `AWS_REGION` 或配置文件中指定的区域。

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
region = "us-west-2"
```

### 与 http 后端共用的选项

以下选项的行为与 http 后端中的说明相同：

- [URL 模板](/dev-tools/backends/http.html#template-variables)和
  [按平台下载](/dev-tools/backends/http.html#platform-specific-urls)
- [`checksum`](/dev-tools/backends/http.html#checksum)和
  [`size`](/dev-tools/backends/http.html#size)
- [`format`、`strip_components`、`bin_path`、`bin` 和 `rename_exe`](/dev-tools/backends/http.html#extracting-and-naming-executables)

与 http 后端不同，s3 后端也会对归档文件应用 `bin`：它会重命名归档中的主可执行文件。若归档中只有一个可执行文件，且未设置 `bin` 或 `rename_exe`，mise 会从文件名中移除操作系统或体系结构后缀，与单文件下载时的处理相同。

`s3` 后端不支持 `checksum_url`、`checksum_expr`、`headers`、`headers_forward`、`shared_extraction`、`windows_script_interpreter` 或 `version_order`。`mise lock` 会记录对象 URL 和已设置的 `checksum`。

## 版本发现

`s3` 后端可通过清单或对象列表发现版本。使用 `latest` 前，请先配置其中一种方式，然后运行 `mise ls-remote s3:my-tool` 检查结果。两者同时设置时，mise 会使用清单。除非工具设置了 `prerelease = true`，否则 `2.0.0-rc1` 等预发布版本不会列出。

### 从清单发现 {#manifest-file}

将 `version_list_url` 设为列出版本的文件的 `s3://` URL：

```toml
[tools."s3:my-tool"]
version = "latest"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
version_list_url = "s3://my-bucket/tools/versions.json"
```

清单可以是版本字符串组成的 JSON 数组，例如 `["1.0.0", "1.1.0", "2.0.0"]`，也可以是 http 后端支持的其他格式。`version_regex`、`version_json_path` 和 `version_expr` 的用法与 [http 后端](/dev-tools/backends/http.html#version-discovery)相同：

```toml
[tools."s3:my-tool"]
version = "latest"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
version_list_url = "s3://my-bucket/tools/releases.json"
version_json_path = ".[].version"
```

mise 会保留清单中的顺序，并将最后一项视为最新版本，因此应按从旧到新的顺序列出版本。

### 从对象列表发现 {#s3-object-listing}

将 `version_prefix` 设为要列出的对象键前缀，不包含存储桶名称。mise 会从 `url` 获取存储桶，列出此前缀下的对象键，并使用 `version_regex` 提取版本：优先使用第一个捕获组；没有捕获组时则使用整个匹配结果。`version_regex` 默认为 `([0-9]+\.[0-9]+\.[0-9]+)`。

```toml
[tools."s3:my-tool"]
version = "latest"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
version_prefix = "tools/my-tool-v"
version_regex = 'my-tool-v(.+)\.tar\.gz$'
```

在此后端中，`version_prefix` 指对象键前缀，而不是 [github 后端](/dev-tools/backends/github.html#version-prefix)中的标签前缀。

S3 会按字母顺序返回对象键，mise 也会保留该顺序，因此 `latest` 对应最后一个匹配项：`1.9.0` 会排在 `1.10.0` 之后。如果版本号的位数不同，请固定版本或改用清单。

## 自定义端点示例（MinIO）

MinIO 服务器的完整配置示例：

```toml
[tools."s3:my-internal-tool"]
version = "latest"
url = "s3://tools-bucket/releases/my-tool-{{ version }}.tar.gz"
endpoint = "https://minio.example.com"
region = "us-east-1"
version_list_url = "s3://tools-bucket/releases/versions.json"
strip_components = 1 # 假设有一个包含 bin/ 的外层目录
bin_path = "bin"
```

通过 AWS 配置文件或标准环境变量提供 MinIO 访问密钥和密钥，然后运行 `mise install`。`https://` 端点必须提供系统信任的证书；本地 `http://` 端点也可使用。

## 故障排除

| 错误                       | 检查内容                                                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Access denied（拒绝访问）   | 所选配置文件或角色、对象读取权限，以及使用 `version_prefix` 时的列表权限。                                     |
| Object not found（对象不存在）| 存储桶、完整对象键、具体版本以及渲染后的平台 URL。                                                            |
| Signature mismatch（签名不匹配）| 凭据、会话令牌、区域、端点和本机时钟。                                                                    |
| No versions（没有版本）    | 清单格式，或对象列表前缀与捕获组。仅有下载 URL 并不能定义版本列表。                                             |
| `latest` 指向旧版本        | 列表或清单的顺序；详见[从对象列表发现](#s3-object-listing)。                                                   |
| 未找到已安装的命令         | 去除顶层目录后的归档结构，以及 `bin` 或 `bin_path` 选项。                                                     |

实现代码：[`src/backend/s3.rs`](https://github.com/jdx/mise/blob/main/src/backend/s3.rs)。
