# S3 后端

`s3` 后端从 Amazon S3 或 MinIO 等 S3 兼容存储中安装二进制文件和归档文件。当访问应遵循你的 AWS 凭据，或版本发现需要列出存储桶中的对象时，请使用它。不需要 AWS CLI。

其代码位于 mise 仓库中的 [`./src/backend/s3.rs`](https://github.com/jdx/mise/blob/main/src/backend/s3.rs)。

## 用法

将下面的存储桶和对象 key 替换为你可以为自己平台读取的构件。对于固定对象 URL，请使用具体版本：

```sh
mise use "s3:my-tool[url=s3://my-bucket/tools/my-tool-v1.0.0.tar.gz]@1.0.0"
```

这会将以下内容写入项目的 `mise.toml`。添加 `-g` 以用于全局配置，并运行 `mise exec -- my-tool --version` 验证安装：

```toml
[tools]
"s3:my-tool" = { version = "1.0.0", url = "s3://my-bucket/tools/my-tool-v1.0.0.tar.gz" }
```

## 身份验证

mise 使用 AWS SDK 的[默认凭据提供程序链](https://docs.aws.amazon.com/sdk-for-rust/latest/dg/credproviders.html)。它支持环境凭据、共享 AWS 配置文件、Web 身份以及容器或实例角色。优先使用现有配置文件或工作负载角色，而不是将长期访问密钥复制到项目配置中。

对于已配置的本地配置文件：

```sh
AWS_PROFILE=development AWS_REGION=us-east-1 mise install
```

临时环境凭据除了 `AWS_ACCESS_KEY_ID` 和 `AWS_SECRET_ACCESS_KEY` 之外，还需要 `AWS_SESSION_TOKEN`。`region` 工具选项可以显式选择存储桶所在的区域。

下载已知对象需要 `s3:GetObject`。通过对象前缀进行发现还需要 `s3:ListBucket`；通过清单进行发现则需要对该清单的读取权限。成功下载对象并不能证明允许进行版本列表查询。

## 工具选项

以下 [tool-options](/dev-tools/#tool-options) 适用于 `s3` 后端——这些配置放在 `mise.toml` 的 `[tools]` 中。

### `url`（必需）

指定用于下载工具的 S3 URL。该 URL 支持使用 <code v-pre>{{ version }}</code> 进行模板替换：

```toml
[tools]
"s3:my-tool" = { version = "1.0.0", url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz" }
```

### `endpoint`

为 MinIO、DigitalOcean Spaces 或自托管 S3 等服务指定自定义的 S3 兼容端点：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
endpoint = "https://minio.example.com"
```

### `region`

指定 S3 存储桶的 AWS 区域：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
region = "us-west-2"
```

### 平台特定 URL

对于需要按平台分别下载的工具，请使用表格格式：

```toml
[tools."s3:my-tool"]
version = "1.0.0"

[tools."s3:my-tool".platforms]
macos-x64 = { url = "s3://my-bucket/tools/my-tool-v1.0.0-macos-x64.tar.gz" }
macos-arm64 = { url = "s3://my-bucket/tools/my-tool-v1.0.0-macos-arm64.tar.gz" }
linux-x64 = { url = "s3://my-bucket/tools/my-tool-v1.0.0-linux-x64.tar.gz" }
```

### `checksum`

设置此版本和对象的预期摘要。将此占位符替换为从可信来源获取的完整摘要：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v1.0.0.tar.gz"
checksum = "sha256:REPLACE_WITH_THE_64_HEX_DIGIT_DIGEST"
```

_你也可以不在这里指定校验和，而是使用 [mise.lock](/dev-tools/mise-lock) 来管理校验和。_

### `size`

检查预期的对象大小（以字节为单位）。下面的数字仅用于说明语法；请将其替换为实际大小。这不能替代校验和：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v1.0.0.tar.gz"
size = "12345678"
```

你可以为不同平台指定不同的大小：

```toml
[tools."s3:my-tool"]
version = "1.0.0"

[tools."s3:my-tool".platforms]
macos-arm64 = { url = "s3://my-bucket/tools/my-tool-v1.0.0-macos-arm64.tar.gz", size = "9876543" }
linux-x64 = { url = "s3://my-bucket/tools/my-tool-v1.0.0-linux-x64.tar.gz", size = "12345678" }
```

### `strip_components`

解压归档时要去除的目录组件数量：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v1.0.0.tar.gz"
strip_components = 1
```

::: info
当 `strip_components` 和 `bin_path` 均未设置时，mise 会自动检测是否应用 `strip_components = 1`。当解压后的归档在根目录中恰好包含一个目录且不包含文件时，就会发生这种情况
:::

### `bin`

将下载的二进制文件重命名为指定名称。当下载单个二进制对象且其名称包含平台特定后缀时，这很有用：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-linux-x86_64"
bin = "my-tool"
```

::: info
下载单个二进制文件（非归档文件）时，mise 会自动从文件名中移除操作系统／架构后缀。例如，`my-tool-linux-x86_64` 会变为 `my-tool`。仅当你需要特定的自定义名称时，才使用 `bin` 选项
:::

### `rename_exe`

从归档中解压后重命名可执行文件。当归档中包含一个名称带有平台特定后缀、但你希望重命名的二进制文件时，这很有用：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v1.0.0-linux.zip"
rename_exe = "my-tool"
```

::: tip
对于归档中二进制文件名称与目标名称不同的情况，请使用 `rename_exe`。对于单个二进制文件下载（非归档），请使用 `bin`
:::

### `bin_path`

指定解压后归档中包含二进制文件的目录。这会禁用自动根目录去除。对于形如 `my-tool-VERSION/bin/my-tool` 的归档，请显式设置这两个选项：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v1.0.0.tar.gz"
strip_components = 1
bin_path = "bin" # 去除外层 my-tool-VERSION 目录后
```

### `format`

当 URL 缺少文件扩展名时，显式指定归档格式：

```toml
[tools."s3:my-tool"]
version = "1.0.0"
url = "s3://my-bucket/tools/my-tool-v1.0.0"
format = "tar.gz"
```

## 版本发现

S3 后端支持清单或对象列表。在使用 `latest` 之前配置其中一种，然后使用 `mise ls-remote s3:my-tool` 检查。示例中使用的是占位存储桶，你必须将其替换为自己的存储桶。

### 清单文件

从存储在 S3 中的 JSON 清单文件获取可用版本：

```toml
[tools."s3:my-tool"]
version = "latest"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
version_list_url = "s3://my-bucket/tools/versions.json"
```

清单文件可以是一个版本字符串的 JSON 数组：

```json
["1.0.0", "1.1.0", "2.0.0"]
```

或者是一个对象数组（使用 `version_json_path` 提取版本）：

```json
[{ "version": "1.0.0" }, { "version": "1.1.0" }, { "version": "2.0.0" }]
```

### `version_json_path`

使用类似 jq 的路径表达式从 JSON 响应中提取版本：

```toml
[tools."s3:my-tool"]
version = "latest"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
version_list_url = "s3://my-bucket/tools/releases.json"
version_json_path = ".[].version"
```

### `version_expr`

使用 [expr-lang](https://expr-lang.org/) 表达式提取版本，以实现复杂的版本提取逻辑：

```toml
[tools."s3:my-tool"]
version = "latest"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
version_list_url = "s3://my-bucket/tools/versions.txt"
version_expr = 'split(body, "\n")'
```

该表达式接收响应正文作为 `body` 变量，并应返回一个版本字符串数组。

### S3 对象列表

通过列出 S3 存储桶中的对象来发现版本：

```toml
[tools."s3:my-tool"]
version = "latest"
url = "s3://my-bucket/tools/my-tool-v{{ version }}.tar.gz"
version_prefix = "tools/my-tool-v"
version_regex = 'my-tool-v(.+)\.tar\.gz$'
```

- `version_prefix`：用于列出对象的 S3 key 前缀
- `version_regex`：用于从对象 key 中提取版本号的正则表达式（使用第一个捕获组）

## 自定义端点示例（MinIO）

以下是一个使用 MinIO 作为 S3 兼容后端的完整示例：

```toml
[tools."s3:my-internal-tool"]
version = "latest"
url = "s3://tools-bucket/releases/my-tool-{{ version }}.tar.gz"
endpoint = "https://minio.example.com"
region = "us-east-1"
version_list_url = "s3://tools-bucket/releases/versions.json"
strip_components = 1 # 假设有一个包含 bin/ 的外层目录
bin_path = "bin"
```

通过 AWS 兼容配置文件或标准环境变量提供 MinIO 访问密钥和私密密钥，然后运行 `mise install`。自定义端点使用路径样式的存储桶寻址；它必须能够通过受信任的 TLS 证书访问。

## 与 HTTP 后端的比较

| 功能             | S3 后端                                             | HTTP 后端                 |
| ---------------- | --------------------------------------------------- | ------------------------- |
| 身份验证         | AWS 凭据（环境变量、~/.aws/credentials、IAM）       | HTTP 身份验证标头         |
| 版本发现         | S3 列表或清单文件                                    | HTTP 端点                 |
| 自定义端点       | 支持（MinIO 等）                                     | 不适用                    |
| 使用场景         | 经过 AWS 身份验证的对象存储                          | 公共或经过身份验证的 HTTP 下载 |

## 故障排除

| 错误                 | 检查项                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------ |
| 访问被拒绝           | 所选配置文件或角色、对象读取权限，以及使用 `version_prefix` 时的列表权限                                   |
| 找不到对象           | 存储桶、完整 key、具体版本和渲染后的平台 URL                                                               |
| 签名不匹配           | 凭据、会话令牌、区域、端点和本地时钟                                                                         |
| 没有版本             | 清单格式或列表前缀及捕获组。仅有下载 URL 并不能定义版本列表                                                 |
| 找不到已安装的命令   | 去除根目录后的归档结构，以及 `bin` 或 `bin_path` 选项                                                        |
