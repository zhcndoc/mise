# 远程任务缓存协议

> [!WARNING]
> 远程任务缓存功能处于实验阶段，目前尚不可配置。本文档定义了首个公开协议，即版本 1。不存在需要保留的更早远程缓存协议。

该协议是一种用于任务输入和输出的安全、内容寻址缓存协议。它不会暴露 mise 的本地缓存目录、清单或归档格式。本地存储属于实现细节，可以使用归档或数据包，而无需更改远程协议。

版本 1 将两类不可变数据分开：

- **内容寻址存储（CAS）**包含由其摘要标识的 Blob 和目录对象。
- **操作结果**将规范任务操作的摘要映射到其输出目录、日志和溯源信息。

这种分离可以在不同任务之间对内容进行去重，支持部分传输和并行传输，并允许服务器在发布缓存命中之前验证所有被引用的内容。

## 术语

- **命名空间**：一种不透明的授权与隔离范围，通常代表组织、仓库、分支、拉取请求或用户。
- **操作**：对任务执行及影响其结果的每个输入的规范描述。
- **操作结果**：操作成功完成后发布的不可变记录。
- **Blob**：CAS 中未经解释的字节。
- **目录对象**：CAS 中描述文件、子目录和符号链接的规范 JSON。
- **摘要**：一种算法、小写十六进制哈希值和未压缩字节长度。
- **提交**：在每个被引用的 CAS 对象都经过验证后发布操作结果。

## 传输与版本控制

版本 1 使用 HTTPS 和 HTTP 语义。携带授权凭据的请求必须使用 HTTPS，
但回环开发服务器（`localhost`、`127.0.0.0/8` 和 `::1`）除外。客户端在发出可见警告后，
可以连接到未经身份验证的非回环 HTTP 服务。此模式既不提供机密性，也不提供服务器真实性：路径上的攻击者可以替换未签名的操作结果及其内部一致的 CAS 图。实现可以使用 HTTP/1.1、HTTP/2 或 HTTP/3。

每个 API 请求都会发送：

| 标头                    | 值                                                             |
| ----------------------- | -------------------------------------------------------------- |
| `Mise-Cache-Protocol`   | `1`                                                            |
| `Mise-Cache-Namespace`  | 操作所使用的命名空间，发现端点除外                             |

URL 前缀 `/v1` 是协议的主版本。兼容性新增功能会作为能力进行声明，无需新的 URL 前缀。不兼容的线路或完整性变更需要使用新的主协议；版本 1 不得作为不兼容实现的别名。

服务器必须忽略未知的 JSON 响应字段。除非协商的能力允许，否则客户端不得发送未知的请求字段。

## 摘要

摘要的 JSON 表示形式为：

```json
{
  "algorithm": "blake3",
  "hash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "size": 1234
}
```

版本 1 定义了 `blake3` 和 `sha256`。服务器会公布其接受的算法。Mise 客户端优先使用 BLAKE3，但对于要求使用 SHA-256 的部署，也可以使用 SHA-256。摘要始终涵盖精确的未压缩字节，并包含其长度。服务器必须拒绝格式错误的哈希值、不支持的算法、负数大小，以及与其声明摘要不匹配的内容。

摘要 URL 组件使用 `/v1/blobs/{algorithm}/{hash}/{size}`。算法和哈希值必须与 JSON 表示形式匹配，且 `size` 是无符号十进制整数。

## 能力

`GET /v1/capabilities` 无需命名空间，并返回协议和服务器限制：

```json
{
  "protocol": { "major": 1, "minor": 0 },
  "digest_algorithms": ["blake3", "sha256"],
  "compressors": ["identity", "zstd"],
  "features": {
    "batch": true,
    "resumable_uploads": true,
    "delegated_transfers": true,
    "signed_results": ["ed25519"]
  },
  "limits": {
    "max_batch_items": 1000,
    "max_inline_blob_bytes": 1048576,
    "max_blob_bytes": 107374182400
  }
}
```

客户端必须遵守所公布的限制，并在可选功能不可用时进行回退。对于不支持的主版本，服务器返回
`426 Upgrade Required`，并在 `Mise-Cache-Protocol` 中包含其支持的主版本。

`GET /v1/status` 是一个运行状况检查端点。成功响应表示 API 进程正在运行；
它不能替代能力协商或授权检查。

## 规范对象

协议 JSON 对象使用 UTF-8，并在其字节被哈希或签名时使用 JSON 规范化方案（RFC 8785）。重复的对象键、无效的 UTF-8、非规范编码，以及无法由声明的模式表示的值，都必须被拒绝。

### 操作描述符

操作描述符包含所有声明会影响任务结果的内容：

```json
{
  "version": 1,
  "task": "build",
  "phase": "run",
  "run": [{ "task": "cargo build --release" }],
  "args": [],
  "shell": null,
  "outputs": ["target/release/widget"],
  "root": "crates/widget",
  "source_hash": "blake3:...",
  "dependency_keys": [],
  "environment": { "PROFILE": "release" },
  "command_inputs": [],
  "vars": {},
  "tools": ["core:rust@1.92.0"],
  "os": "linux",
  "arch": "x86_64"
}
```

顺序不具有任务含义的数组必须按照其模式定义的字段进行排序。版本字符串是不透明的，绝不会按语义排序。操作描述符中不得出现机密信息。仅当任务声明环境变量为缓存输入时，才会将其纳入其中。

`source_hash` 绑定所声明的源路径及其内容，而不会上传缓存专用操作不需要的任务输入。规范描述符存储在 CAS 中。其摘要即为操作摘要和操作结果 URL 键。描述相同操作的两个客户端必须生成完全相同的规范字节。

### 目录对象

目录对象的媒体类型为 `application/vnd.mise.cache-directory.v1+json`：

```json
{
  "version": 1,
  "directories": [
    {
      "name": "assets",
      "digest": { "algorithm": "blake3", "hash": "...", "size": 321 },
      "mode": 493
    }
  ],
  "files": [
    {
      "name": "widget",
      "digest": { "algorithm": "blake3", "hash": "...", "size": 123456 },
      "executable": true,
      "mode": 493
    }
  ],
  "symlinks": [{ "name": "current", "target": "widget", "mode": 511 }]
}
```

每个节点列表都按照 `name` 的 UTF-8 字节排序。名称必须是单一路径组件，不得为空、不得为 `.` 或 `..`，不得包含斜杠或 NUL，也不得与其他节点冲突。在恢复期间，必须拒绝绝对符号链接目标，以及会逃逸出所声明输出根目录的目标。

可移植元数据集合包括文件内容、目录结构、符号链接、可执行状态，以及由 `mode` 表示的可移植权限位。所有者、组、时间戳、设备、套接字、FIFO、平台 ACL 和扩展属性都不会被恢复。硬链接可以作为独立文件恢复。不受支持的源对象会使任务结果不具备远程缓存资格，而不会被悄然更改。

### 操作结果

操作结果响应和提交正文的媒体类型为
`application/vnd.mise.cache-action-result.v1+json`。线上的对象始终是一个信封，因此未签名结果和已签名结果具有相同的模式：

```json
{
  "result": {
    "version": 1,
    "action": { "algorithm": "blake3", "hash": "...", "size": 789 },
    "output_root": { "algorithm": "blake3", "hash": "...", "size": 456 },
    "metadata": { "algorithm": "blake3", "hash": "...", "size": 234 }
  },
  "signatures": []
}
```

只有成功且可缓存的任务执行结果才能被发布。当任务没有声明输出文件时，`output_root` 不存在。`metadata` 引用规范的 `application/vnd.mise.cache-client-metadata.v1+json`，其中包含 mise 客户端所需的输出根目录、捕获的输出、任务标识、恢复字节数估算值和执行持续时间。元数据模式是远程协议的一部分，并且独立于 mise 的本地缓存清单。

```json
{
  "version": 1,
  "task_identity": "build:crates/widget",
  "roots": ["target/release/widget"],
  "output": [{ "stream": "stdout", "line": "built widget" }],
  "restored_bytes": 123456,
  "execution_duration_ns": 900000000
}
```

根路径使用正斜杠，相对于任务工作目录，并且必须满足与目录节点相同的路径安全规则。输出条目保留其声明的顺序。

在结果变为可读之前，操作描述符以及从结果可到达的每个对象都必须存在并通过验证。经过身份验证的生产者身份、代码库、修订版本、CI 运行和提交时间由服务器记录在不可变结果旁，并包含在签名回执中；客户端无法通过在结果正文中放置声明来确立自身可信的来源信息。

保留期限、最后访问时间、配额核算、内部存储位置和服务器注释都不属于不可变操作结果。

## CAS 操作

### 查找缺失的 blob

`POST /v1/blobs:missing` 接受 `application/vnd.mise.cache-digests.v1+json`：

```json
{ "digests": [{ "algorithm": "blake3", "hash": "...", "size": 1234 }] }
```

对于已验证的 CAS 中不存在的对象，返回其中的子集，状态为 `200 OK`：

```json
{ "missing": [{ "algorithm": "blake3", "hash": "...", "size": 1234 }] }
```

服务器不得披露请求者可读命名空间或 CAS 可见性域之外是否存在对象。

### 读取 blob

`GET /v1/blobs/{algorithm}/{hash}/{size}` 在调用方可以读取对象时返回 `200 OK`，否则返回
`404 Not Found`。响应包含 `Digest` 和 `Content-Length` 元数据。服务器可以支持
`Range`，也可以返回协商后的 `Content-Encoding: zstd`；URL 中的摘要始终描述
未压缩的字节。

声明支持委托传输的服务器可以将请求重定向（`307 Temporary Redirect`）到一个短时有效的 HTTPS
URL。重定向只能授予对所请求不可变对象的访问权限。客户端不得将缓存服务的
`Authorization` 标头转发给委托主机。

客户端在使用下载内容前会验证完整的未压缩摘要。摘要不匹配时视为缓存未命中，发出可见的完整性警告；
启用报告能力后，还必须将其报告到服务器遥测系统。

### 上传 blob

较小的 blob 可以直接通过
`PUT /v1/blobs/{algorithm}/{hash}/{size}` 和 `If-None-Match: *` 发送。服务器返回：

- 验证并发布新内容后返回 `201 Created`；
- 已存在相同的已验证内容时返回 `204 No Content`；
- 字节内容与摘要不匹配时返回 `400 Bad Request`；
- 不可变前置条件失败时返回 `412 Precondition Failed`；
- 超出公布的限制时返回 `413 Content Too Large`。

较大或可恢复的上传使用上传会话：

1. `POST /v1/uploads` 声明一个或多个摘要。
2. 服务器返回上传 ID、过期时间、偏移量，以及服务器上传 URL 或委托上传 URL。
3. 客户端上传分块，并在必要时从服务器确认的偏移量处恢复。
4. `POST /v1/uploads/{id}/finalize` 验证完整内容，并将其提升到 CAS 中。

委托上传始终以隔离的暂存键为目标，绝不会使用可读的 CAS 键。因此，仅提供预签名的 S3
上传是不够的：最终确认发布前必须验证所声明的摘要。过期或被放弃的暂存对象会被异步删除。

## 操作结果操作

`GET /v1/action-results/{algorithm}/{hash}/{size}` 返回已提交的操作结果，或返回 `404 Not
Found`。命名空间标识该请求的单一读取范围。配置了多个读取范围的客户端会按照策略顺序查询这些范围，而不是发送含义不明确的多命名空间请求。

`PUT /v1/action-results/{algorithm}/{hash}/{size}` 提交操作结果。该请求要求使用
`If-None-Match: *`。服务器必须以原子方式：

1. 授权对该命名空间的写入；
2. 验证 URL 摘要与结果及已存储的操作描述符相匹配；
3. 验证策略要求的结果模式和签名；
4. 验证完整的可达目录和 blob 图；
5. 记录经身份验证的生产者来源信息；
6. 发布不可变映射。

响应为 `201 Created`；对于相同的已提交结果，响应为 `204 No Content`；当已有不同结果占用该操作键时，响应为 `409 Conflict`；当缺少不可变前置条件或前置条件验证失败时，响应为 `412 Precondition Failed`。并发的有效写入者可以上传相同的 CAS 数据，但只有一个操作结果提交能够成功。

普通缓存写入者不会获得删除权限。管理性删除使用单独授权的端点，并且必须在不可达的 CAS 数据被垃圾回收之前移除操作结果映射。客户端缓存清除操作不得意味着有权删除共享的远程数据。

## 签名与来源证明

CAS 摘要提供完整性保证，但无法证明是谁将某个操作与输出关联起来。因此，操作结果信封可能包含签名：

```json
{
  "result": {
    "version": 1,
    "action": { "algorithm": "blake3", "hash": "...", "size": 789 }
  },
  "signatures": [
    {
      "algorithm": "ed25519",
      "key_id": "cache.example.com/2026-08",
      "signature": "..."
    }
  ]
}
```

签名输入由 ASCII 域分隔符 `mise-cache-action-result-v1`、一个 NUL 字节以及 `result` 的规范 JSON 字节组成。版本 1 定义了 Ed25519 签名。服务器还可以保留 CI 身份证明，并签发带签名的提交收据。

配置为要求签名的客户端会将缺失、未知或无效的签名视为缓存未命中，并显示警告。公钥验证密钥属于配置；私有签名密钥不得分发给不受信任的客户端。共享密钥 HMAC 不是默认选项，因为任何持有该密钥的验证者都可以伪造结果。

## 身份验证与命名空间策略

该协议支持持有者令牌、OIDC 派生令牌、mTLS 以及受信任的反向代理身份。
身份验证机制的发现属于部署配置，而不是 CAS 对象元数据。
凭据必须进行作用域限定，并从诊断信息中脱敏。

服务器独立授权读取和写入操作。安全的部署至少应提供：

- 仅允许受保护分支或其他受信任 CI 写入的共享命名空间；
- 为不受信任的拉取请求作业提供只读共享访问；
- 为拉取请求和开发者提供隔离的写入命名空间；
- 当隔离结果应成为共享结果时，提供显式的受信任提升操作。

不可变存储无法阻止首个写入者投毒缓存。即使后端对象存储拒绝覆盖，也仍需要命名空间授权、
生产者来源和签名策略。由受信任和不受信任作业共享的单一存储桶凭据，不构成符合要求的
安全边界。

## 失败与重试行为

- `401 Unauthorized` 表示缺少身份验证或身份验证无效。
- `403 Forbidden` 表示该身份无权访问请求的命名空间或执行请求的操作。
- `404 Not Found` 表示缓存未命中，且不得泄露无法访问的对象。
- `409 Conflict` 表示不可变操作结果冲突。
- `412 Precondition Failed` 表示缺少条件写入要求，或该要求未通过。
- `422 Unprocessable Content` 表示对象编码有效，但其引用图无效。
- `426 Upgrade Required` 表示主版本不匹配。
- `429 Too Many Requests` 和 `5xx` 响应可以使用有界指数退避和
  抖动进行重试，并遵循 `Retry-After`。

缓存不可用、对象格式错误、引用的对象缺失以及完整性失败通常会降级为缓存未命中，以便本地任务继续执行。身份验证、授权和完整性失败仍必须产生可见警告；客户端不得将其静默标记为普通未命中。部署可以启用严格模式，使选定的失败成为致命错误。

幂等性密钥可以用于上传会话创建及其他可重试的 `POST` 操作。服务器必须限制其保留时间，并将其作用域限定为经过身份验证的身份和命名空间。

## 自托管存储要求

符合规范的自托管服务器可以使用文件系统、兼容 S3 的对象存储或其他 Blob
存储。客户端与缓存服务通信，而不是获取通用对象存储凭据。

官方参考服务器单独维护于
[`jdx/mise-cache`](https://github.com/jdx/mise-cache)。它提供文件系统和兼容 S3 的 Blob
存储、PostgreSQL 元数据、命名空间范围的授权、Docker Compose 以及 Helm chart。服务器的部署和发布生命周期仍与 mise 客户端分离，而本文档是规范协议的权威说明。

使用 S3 的服务器应：

- 将操作元数据、授权信息、来源信息、访问时间、引用关系和配额存储在事务性元数据存储中；
- 将 CAS 字节存储在基于摘要派生的不可变键下；
- 为委托上传使用随机暂存键；
- 使用有条件的对象创建，并拒绝普通的覆盖和删除权限；
- 仅在验证每个可达对象后，才完成操作结果；
- 对过期的暂存上传和不可达的 CAS 对象进行垃圾回收；
- 支持短期工作负载凭据和静态加密。

对象存储版本控制、保留锁和加密是有用的纵深防御措施，但不能替代应用授权或摘要验证。

## 一致性

仓库的兼容性套件是所要求的版本 1 行为的可执行定义。
它必须涵盖能力协商、规范对象验证、命名空间隔离、独立的读写授权、缺失 blob 批次、流式传输和可恢复传输、摘要拒绝、
原子操作结果提交、不可变冲突、委托传输凭据隔离、签名、损坏处理以及重试语义。

服务器可以在 `/v1` 之外实现额外的管理、指标和健康检查 API。这些 API
不得削弱版本 1 的缓存不变量。
